# Root command-line carry gate

These tools own fresh x64 execution and a separately authored machine oracle.
They preserve the earlier filename and mainargs tools and evidence unchanged.

`run.py` admits an externally supplied successful build SHA, runs both workers
through timed shell-free stages, and packs each retained capture tree into an
externally SHA-bound archive. It verifies the declared 24 ordinary and twelve
causal requests per worker. Stage success alone is not equivalence evidence.

`model.py` uses the frozen original FDIV BEFORE capture and accepted independent
source interpreters for the earlier startup chain. At the explicit late seam it
models the actual source CALL and MOV, measured native command-line input,
owned guest allocation, PC-only transport and EAX carry. `consumer.py` decodes
and checks the real source continuation, including CMP8 flags and successful
stores before ESP publication. The parser body remains outside the gate.

`observe.py` compares all 48 ordinary rows: complete State, FX, RuntimeCPU,
sixteen borrowed pages, source snapshots, NUL-inclusive owned bytes, preceding
ledgers and the new producer/consumer access and route records. Actual new API
results are declared external inputs; no native AFTER machine is a model seed.
The measured command line must match the root launch request. Loaded API
identity, memory regions and module hashes are separately checked.

The native credited domain contains nonempty command lines for these workers.
The oracle structurally represents the source empty-string branch without
claiming that branch was natively executed. Standard causal row identities are
checked by the root runner; their complete machine outcomes are not claimed
as independently modeled by this oracle. An independent compiled reviewer
supplies the additional lifecycle, token, partial-store and host-boundary proof.

`preview.py` is a preserved development check over an older author capture.
It supplies no root execution or final admission credit. Failed stages and
superseded receipts must remain separately identified. Final acceptance must
hash the complete current physical dependency closure; historical receipt
hashes preserve history without expanding obsolete source bindings.
