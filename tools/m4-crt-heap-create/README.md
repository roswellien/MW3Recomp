# Genuine owned HeapCreate bridge research

This isolated AMD64 worker extends the accepted heap-initializer prefix. All 26 prior guest COFF objects and both FDIV libraries are reused byte for byte. The original game and CRT provider remain pinned data inputs; neither executable is launched.

The explicit scheduler changes only carried guest State EIP to the exact original seven-byte attach fragment at `7800183C`. The fragment itself pushes argument one and calls the exact compiled provider at `780039BF`. State ESP, the generic Runtime CPU and its call records remain unchanged at the host scheduling seam. A new eighteenth guest page at `78035000` is mapped from the entire pinned original raw RW page before every capture. Its first words are original file values, not initialized host globals.

The original `CALL [7802E0A8]` executes its IAT read and return-word store. The bridge verifies the unique original `KERNEL32.dll!HeapCreate` metadata, raw token `0003461E`, source CALL frame and arguments `[0, 4096, 0]`. It measures the actual loaded creator and cleanup API exports, owning modules, code regions, file paths and hashes.

The actual host `HeapCreate(0, 4096, 0)` result is assigned immediately into a private fixed owner slot before any operation that can allocate or throw. That slot stores the complete x64 `HANDLE`. A successful result is registered under independent opaque guest DWORD `48450001`, whose meaning is restricted to this binding and lifetime. This bounded one-heap experiment does not establish a general multiheap token registry. Guest tokens never contain truncated host handles.

The bridge separately checks the source return word at `20001848` and admits a finite guest stdcall model: only low EAX receives the token or zero, low ESP advances by 16 to `20001858`, and low EIP becomes `780039D6`. Every other carried State byte, Runtime CPU and FX remains preserved. This is the declared guest API model; it is not a universal equivalence claim about unobserved original x86 API volatile registers or flags.

The API bridge returns naturally from `__remill_function_call`. The same frozen provider invocation then executes its original TEST, global MOV, conditional branch and direct CALL. The source publishes the opaque token at `78035000`; the host performs no global publication. Ordinary runs reach `78003A0C` through the real CALL at `780039E3`, retaining its source return word `780039E8` at `20001854`, and refuse before the unresolved mode selector body. Thirteen source PCs and ten original source DWORD accesses execute, plus one separately recorded API return read. The reused source bodies cover 84 bytes; 48 source bytes execute along this success path.

Both XOR at `780039BF` and TEST at `780039D6` have architecturally undefined AF. The exact compiled scalar bridge admits recorded representative zero at these two sites only. TEST derives its other flags from the opaque token. No universal original-CPU AF value is claimed.

Private ownership drives real `HeapDestroy` cleanup on every experiment exit, including observer exceptions, registration rollback and partial source faults. A failed OS destruction retains ownership and its failure record until a real successful release; it is never reported as closed merely because cleanup was attempted. Public witnesses and tokens cannot substitute a handle for cleanup. The source-written guest global retains its diagnostic token after this experiment closes its host heap; it does not represent a live heap after cleanup.

Every full phase captures all 18 raw pages, State, FX, Runtime CPU and the original source fields. Two additional phase records show the measured API witness and registry lifetime. They are zero before the known heap producer is scheduled, show live ownership at the mode frontier, and show closure after cleanup. Their capture association is private, so corrupt public binding tokens cannot cause an invalid pointer dereference during fault reporting.

Author controls 121 through 132 cover injected NULL result, immediate post-creation exception, registration rollback, witness mutation, a partial API return read, return projection mutation, post-publication exception, checked global/stack write refusal, mode source mutation, terminal observer exception and an injected cleanup skip. The NULL and cleanup skip controls explicitly describe test seam provenance. NULL skips the OS create call and lets original TEST/MOV-zero/JE reach the unadmitted cold target `7800CDDC`; its RET is not executed. Cleanup skip refuses before the OS destroy call, retains ownership, then performs the real fallback release. Neither seam is claimed as an actual OS failure.

`prepare.py` derives only additive adapters and checked bridges. `build.ps1` records compiler, header, source, object and library identities. `run.py` executes 36 bounded sequences per optimization, records real creator and destructor counts, verifies exact full-handle cleanup identity and strictly packs every capture. Independent source, original-BEFORE and compiled/hardware review remain separate proof domains.

No allocator mode, mode-selector body, successful initializer RET, locale initialization, parser completion, original DllMain/attach scheduling, standalone game window, full CRT startup or full M4 completion is credited by this gate.
