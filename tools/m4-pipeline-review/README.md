Independent acceptance for the new capture transport and stage receipts.

`capture_schema.py` inventories representative immutable O0/O2 mainargs captures
and rehashes every selected old artifact against its sealed manifest. This records
positive, early producer failure, and late provider failure shapes without another
native or original execution.

The concrete candidate review must establish:

- Exact path-to-byte equality, determinism, embedded per-file hashes, and whole
  bundle identity across independent success roundtrips.
- Strict bounded parsing before publication or byte access, canonical relative
  paths, normalized duplicates, invalid extents, counts, oversized members,
  malformed metadata, bad hashes, truncation, and appended data refusals.
- Failed writes preserve existing final destinations and never publish complete
  success; temporary or interrupted captures cannot masquerade as sealed bundles.
- Merged dependency manifests preserve every input binding, reject normalized
  conflicting hashes, and still support complete final physical closure.
- Stage receipts bind the actual command, working directory, output hashes,
  exit status, and measured monotonic duration. Failed subprocesses and interrupted
  stages remain inspectable and do not publish a false success receipt.

Transport equivalence grants no new guest behavior or weaker memory, FP, unwind,
pointer, or final physical-binding acceptance rules.

Reserved Windows aliases include device names with extensions and COM/LPT
superscript digits. The corpus follows [Microsoft's file naming rules](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)
and the pipeline's stricter canonical-path policy.
