# Frozen hardware review through capture bundles

This additive transport binds the accepted command-line carry fixture build,
compiled review, hardware observer and unchanged validator sources by external
SHA256. It packs both complete `actual` trees, compares every logical name,
extent, hash and byte with the frozen build artifact manifest, then invokes the
exact old `host_pair` and nested `validate` function bodies through a strict
logical read adapter. It runs no native code and changes no old artifacts.

`prepare.py` publishes fresh full-tree bundles and byte-equivalence inventories.
`review.py` requires the external preparation report SHA, checks all 264 actual
raw80/legacy hardware pairs and the same 548 semantic corruptions, exercises
aggregate/path/inventory denials through the normal reader, and measures the
same semantic workload with strict flat and retained-bundle readers.

Packing and entry-equivalence proof, reader startup/full verification, and
repeated warm validation are reported separately. Fresh-reader startup follows
packing and does not establish an OS-cold cache. The baseline flat timing uses
the same additive adapter; it does not measure the entire earlier review script.
The new proof preserves the frozen compiled fixture assertions and decoder
receipt as historical identities, while physically hashing all current tools,
sources, receipts, noncapture native artifacts and bundles. Original captured
files cease to be current physical dependencies only after complete pinned
inventory and byte equivalence. No metadata-only cache or extraction is used.
