# Work-area initializer experiment

This separate gate covers table slot `0x5E0110`, root `0x482CF0`, and its exact reached 22-instruction body. The native caller is a bounded hand translation with typed Remill State serialization, checked guest memory, and a real host Win32 query. It has no Remill lift or connected startup admission and does not change the shared runtime.

The initializer copies 24 original bytes from `0x5E6000` to object `0x608F88`, then calls the owning `USER32.dll!SystemParametersInfoA` IAT slot `0x5BB6DC` at `0x482CDD`. The four stdcall arguments are action `0x30`, zero, output `0x608FA0`, zero; return continuation is `0x482CE3` and argument cleanup is 16 bytes. The action is [SPI_GETWORKAREA](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-systemparametersinfoa), a query for the primary display work area in physical pixels. RECT comprises four signed 32-bit values and 16 bytes. The source, reached bytes, exact image and current 32/64-bit USER32 disk identities are private hash-bound inputs.

The native bridge calls the host query with an owned host RECT initialized from the 16 existing guest bytes, then copies its actual 16 bytes through checked guest memory. Guest addresses never become host pointers. Its exact read-only arguments, owning IAT, call site, frame, continuation, flat DS/ES/SS bases and DF0 are checked before the query. Six prefix stores establish the permission of the same guest mapping before the API runs. Context reuse and lifetime violations are rejected. The initializer discards the Boolean result, restores EBX/ESI/EDI, preserves EBP, and returns object address `0x608F88`. It does not manufacture a rectangle or convert a false API result into success. All actual captures returned nonzero BOOL; zero and unusual nonzero results are separately authored fixtures, with no actual false-query execution credit.

ECX/EDX and arithmetic flags after the import are unspecified by the service ABI and are not consumed by the reached continuation, which contains only POP, MOV and RET. Their full actual original values remain in private captures. The native representative policy keeps incoming EDX/flags and the caller's exhausted ECX0; it establishes no equality for original volatile outputs. Original SIMD data changes, including first-query XMM6/7 changes, are retained as observations and are not consumed by the reached caller. Native software FP/SIMD is preserved as an explicit representative policy. Actual unchanged original x87/MXCSR/legacy ENV matches in this domain are observation evidence, not a general Windows-provider FP guarantee.

The x86 original/provider broker is a separate experiment for original observations and ABI characterization. It executes the sparse original caller on its diagnostic frame, copies the four exact query arguments to the real Windows thread stack, and calls the actual resolved 32-bit provider there. Both physical provider ESP values are observed; their 20-byte advance proves return plus stdcall16 cleanup. Logical guest ESP is an explicit transport projection. The original CALL return word is preserved, then the actual POP/MOV/RET continuation runs. Broker PC fields are authored call-site/continuation metadata; they are not sampled hardware EIP. This broker is never the final native backend.

The normal Windows captures contain 144 actual original records and 288 native records across 12 fully masked control words, empty TOP0/TOP7, three dirty object/register/flag/vector variants, and two repeats. The observer checks whole CPU, three complete pages before/after, full native 3504-byte State, native 34 ordered memory events, actual provider RECT and physical stack snapshots, actual host restoration, and separate hardware FX/legacy ENV. Original State and per-access events were not observed. Native guest FX/ENV is a software projection; native provider FX/ENV separately observes the actual host query. The observer retains all original fields, verifies their actual carry to the final caller, and compares only service-defined outputs across implementations. Environment-dependent query results must agree in the captured desktop; no dimensions are hardcoded.

There are 24 actual compiled context/restoration/reuse controls per native level, 52 observer corruptions rejected per level, and four synchronized original volatile/vector changes accepted as unspecified. Separate authored controls compile the same caller/query body with private Context access exposed and only the host-query token replaced: 15 pre-query denials, three BOOL/RECT transport fixtures, and three real output-ownership controls per level. These authored fixtures grant no actual-provider credit. Twelve actual worker input/publication denials reject before any original body or native query; four recipe controls preserve pre-existing partial/nested report or derived build directories before input/source access or writes.

Earlier shell, provider-load, unclassified original access-violation, sandbox address-reservation and authored-control compile failures remain private with literal prior sources. The passing gate uses the ordinary Windows context. Output publication owns a CREATE_NEW staging handle and refuses existing destinations. The admitted filesystem scope is sequential private ordinary directories; concurrent destination writers and reparse-point safety are outside this gate. Provider disk hashes are checked after module load and compiler dependency hashes after build; neither is a complete execution-time process/module trace. No game/window launch, settings change, shared runtime integration, or complete startup credit is claimed.
