# Installer preparation: generate support inputs from user media

This step removes required original support-image lookups in the development
checkout from the installed runtime path. It also replaces two copied derived
inputs with local generation from the player's original files. It does **not**
complete the playable installer: generation of the compiled native host and
translated entry object remains open, and no Setup EXE was compiled this turn.
Strict acceptance remains **131/144**.

## Implemented setup boundary

`SupportedMedia.json` now pins four user-provided support images extracted from
the admitted retail cabinet: MSVCRT, MFC42, MSVCP50 and Ir50_32. ISO installation
copies those into `native-inputs` alongside the 147 game/media files. The
existing-install route imports the same four into content-addressed user storage
without changing the selected original installation. The verified extractor
reads the Shared DLLs and Codec DLLs groups; original installers, DLLs and game
executables are not executed.

`GameInstallation.PrepareSupportFiles` verifies the inputs and generates:

| Resource | User input | Generated SHA-256 |
| --- | --- | --- |
| Rebased movie decoder image | Original Ir50_32.dll | `9d066dbdb0b9903c2afb07284d609c7d3ed3278245040490e9805d4cd717958f` |
| Startup source-page pack | Original MSVCRT.DLL | `fd9a41958ac2edf5e1c3f118ec24a59e2df295d94ac1d1b1346deb3cbc46aa80` |

The codec preparation applies PE32 HIGHLOW relocations and updates ImageBase,
with bounds/type checks. It produces the same 739,328 bytes as the prior private
Python derivation. It is original input data for the translated decoder, not
a DLL loaded for original-code execution. This is essential original-movie
support; enhanced cinematic work remains deferred.

`CrtSourcePack.Build` independently reproduces the existing 28,740-byte
`MW4FDIP1` contract from the pinned CRT image: five recovered source ranges,
two original data pages, three readonly constants and fixed 0xCC padding.
Addresses and lengths are authored metadata; all original payload bytes come
from the player's input. It matches the historical pack byte for byte. No
captured BEFORE/AFTER memory or fabricated initializer state is used.

Generated files publish atomically into content-addressed per-user storage.
Corrupt generated cache entries are repaired, retaining the rejected copy;
unknown or damaged source images reject. Existing user originals remain
unchanged. The source/derived files are not bundled into Runtime or the
launcher installer. Local generation does not authorize redistributing them.
