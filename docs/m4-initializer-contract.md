# First M4 startup initializer gate

This gate covers the complete initializer wrapper at `0x00410910` and its tail destination, the complete body at `0x00410920..0x00410934`. The hash-admitted executable's CRT initialization table stores the wrapper pointer at `0x005E0058`. Other startup initializers, CRT exception handling, MFC application initialization and menus remain outside this gate.

The body clears one byte in each of 167 records, starting at `0x00604130`, with a 20-byte stride and final write at `0x00604E28`. The offline comparison seeds all data bytes so unchanged record padding is observed. The image's page at `0x00604000` is virtual zero-fill; seeded comparison data is an authored perturbation, not a captured startup recording.

The entry is flat x86 with a valid four-byte return frame wholly in the admitted stack page and no other stack parameters. On return EAX is `0x00604E3C`, ECX is zero, ESP advances four bytes and PC equals the return sentinel. Other general registers persist. Final ADD establishes CF=0; final DEC defines PF=1, AF=0, ZF=1, SF=0 and OF=0. DF persists. All arithmetic exit flags, including AF, are compared with mask `0xCD5`; none is excluded.

The native component uses statically lifted Remill IR compiled for Windows x64 at O0 and O2. All guest pointers stay 32-bit values and cross checked byte-write and dword-read bridges. The only bridge events are 167 ordered byte writes followed by the return-address dword read. The bridge preserves the actual emitted value; the independent arithmetic and memory oracle judges it. Original hardware does not observe Remill State or individual memory events, so those original fields are explicitly zero and unobserved. Native State and bridge events are actual observations.

The admitted FP seed domain retains M3's twelve masked x87 control words, all TOP and physical occupancy combinations, coherent occupied canonical raw80 values and arbitrary raw storage in empty slots, status flags, eight guest XMM registers and fixed MXCSR. Guest FOP/FIP/FDP must each be zero and are still compared exactly in actual FX and legacy environment captures. Nonzero guest pointer/opcode metadata, arbitrary unmasked traps and high 64-bit host pointers are excluded. Native host isolation preserves immediately captured host storage and legacy environment on normal and checked fault paths; it does not claim arbitrary exception unwinding across generated frames.

Before any body or output is admitted, each worker checks the complete image and wrapper/body identity and every request. Original execution uses an isolated, suspended child with fixed guest reservations made before CRT startup. Its broker is a new authored copy with the M4 address ranges; existing M3 sources and evidence remain unchanged. The failure-only native escape crosses pure generated code after bridge exception objects have been destroyed. Partial results never become successful output.

Both workers admit staging-path absence before constructing their cleanup owner. An external sentinel control invokes that same compiled ownership helper and requires exit 1 with the staging-collision diagnostic, no result file, and exact preservation of the pre-existing sentinel. These filesystem checks are separate from the 32 compiled protocol controls.

The build recipe requires an entirely new private report directory and all three derived build directories (reference, O0 and O2). It rejects collisions before source capture, private image resolution, extraction or compilation. Real recipe controls retain authored markers in an existing partial report and each existing build directory, checking that rejection preserves the complete observed inventories and creates no other candidate output. Reusing a leaf name under another nested report path still requires fresh derived build directories.

Completing this gate is an M4 prerequisite. It does not mean the game reaches native menus or that the remaining 143 initializer bodies and MFC callback graph have been translated.
