# Connected game control wrapper experiment

This gate connects the complete game wrapper at `0x5AC5A0`, its import thunk at `0x5AC5D6`, and the four previously reviewed static MSVCRT control functions through a fresh adapter using unchanged shared Runtime r9. The author comparison passes 192 actual original records and 384 actual native records at O0/O2 with zero differences under the declared capture-PC projection. Independent raw models pass separately; final source, build, and compiled causal closure review is still required. Full CRT startup, a following numerical callback, and M4 completion remain open.

The wrapper pushes `mask=0x30000` and `new=0x10000`, calls the thunk, adds eight to ESP, and returns. The thunk performs the actual indirect tail jump through the named `MSVCRT.dll!_controlfp` IAT slot `0x5BB578`. The native image retains its original raw IAT DWORD `0x1DED8A`; it is never replaced with a host function pointer. Exact wrapper, thunk, outer CALL, and provider source slices are checked against the admitted images. The provider executes the same accepted typed FNSTCW/FLDCW lowering as the standalone control gate.

## Existing frame and persistent state

The source CRT CALL at `0x5AC431` has return word `0x5AC436`. This is a checked outer boundary; the rest of the CRT entry is not executed. The compiled wrapper performs its own CALL to the thunk and pushes provider continuation `0x5AC5AF`. At the tail port, the adapter requires that exact already-pushed frame and arguments. It projects Runtime CPU ESP one word above the existing frame, then uses unchanged r9 `call_import`, which writes the same continuation DWORD at the same address. This is an explicit service orchestration convention, with no additional guest CALL instruction or extra return word. The compiled provider returns to `0x5AC5AF`; the compiled wrapper then executes its actual `ADD ESP,8` and RET.

All callbacks borrow one checked GuestMemory and one complete 3,504-byte persistent Remill State. The separate 512-byte FX view and 28-byte legacy environment retain their distinct measured representations. Integer/provider callbacks preserve nonzero legacy FOP/FIP/FDP fields, hidden State bytes, and guest FS base. Each native record contains the full pre/post State, complete 4,096-byte stack, separate FX and legacy environment, thirteen actual entry/return/tail events, two completed r9 routing records, and actual host FX/environment restoration. Original inputs alone initialize native execution; original AFTER values are not execution inputs.

The original worker captures at literal instrumentation PC `0x10000100`, reached by an authored jump from the real outer continuation `0x5AC436`. Native execution returns at the literal admitted game PC `0x5AC436`. Comparison projects only that instrumentation PC; it requires both original and native PCs separately. It otherwise compares every CPU register and complete FLAGS, memory, FX, and legacy environment. The wrapper's final ADD defines AF as well as CF/PF/ZF/SF/OF: the checked flag mask is `0xCD5` with zero undefined-flag exclusions. CPL3 POPFD cannot clear IF; the requested `0x802` input is recorded as actual `0xA02` rather than treated as an IF-clear execution.

## Bounded domain and controls

The corpus uses twelve masked incoming CW values, eight directed register/FLAGS/stack positions, and two repeats. It admits empty TOP0, SW0, empty FTW, matching State/FX CW, zero pending shadow status, and MXCSR `0x1F80`. It preserves nonzero raw 80-bit storage, XMM input, and legacy metadata. This control operation performs no following numerical x87 instruction. Pending exceptions, live x87 stacks, unsupported state, numerical host-CW synchronization, and complete CRT exception handling are outside this gate.

There are 29 actual worker input/output controls with their intended diagnostics, 180 author raw observer corruptions, and 125 compiled context checks across 22 semantic scenarios at each optimization. Compiled controls cover missing import service, nested frame capacity, missing/readonly stack, guest FS and flat-segment identity, unsupported FP state, separate-CW mismatch, changed game/IAT/provider sources, unreadable provider code, absent serial owner, boundary capacity, incomplete routing after fault, retained first faults, poisoned reuse, and actual host restoration. Missing services do not receive invented successful return values.

Execution is serial in fresh private ordinary directories with a trusted stable Context/Runtime borrower. Concurrent writers, reparse points, dangling links, arbitrary host mapping/permission replacement, production publishing, and swallowed arbitrary raw GuestMemory faults are not admitted. Source hashes and recorded compiled artifact identities require the separate build/review association; registry metadata alone is not attestation. No general thread-owned or one-use production callback API is claimed.

## Preserved attempts and reproducibility

Their raw streams, diagnostics, literal source copies, build, and commands remain preserved and grant no causal control acceptance.
