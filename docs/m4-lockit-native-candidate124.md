# Four-root Lockit native candidate

Updated 2026-10-09. Roots `411010`, `4DC140`, `500660` and `5968F0` now have
[final acceptance](m4-progress-startup124.md): **124/144**, with **20 remaining**.
This record retains the candidate's implementation and validation details.

## Completed evidence

- The authentic original DLL loader established MSVCP state2 and its initialized
  critical-section input. Balanced ordinary and recursive Lockit probes passed.
- The original full 124-root schedule passed six sequences: 744 root calls,
  96 ordered registrations per sequence and 43 observed pages.
- Independent source reconstruction verified the four new original prefixes,
  144 CPU/FX/environment/frame boundaries, all eight new allocation backings,
  complete 32-byte owner carries and cleanup. The original requests six 24-byte
  and two 20-byte objects; actual acquired capacities are 32 bytes.
- Static owner derivation and all six original sequences agree on 32 exact
  requested-bound stores and eight pointer publications.
- The literal game and provider bodies compile at O0 and O2. Final build r4
  links 363 literal, 27 compiled and two capture objects per level. Independent
  review confirms the unchanged 159,716-byte native record and 43 source pages.
- The isolated native test passes all four roots at both levels, with eight
  completed Lockit CALL/RET pairs, four restored normal exception-chain records,
  eight new allocations and actual resource cleanup.

The native resource is a distinct real Windows critical section. Its 40-byte
host object supplies the observed serial field semantics of the 24-byte guest
object. Authentic loaded inputs and exact named API cells remain bound; the
association does not claim to execute native MSVCP DllMain or its lazy path.

## Current validation

The full native 124-root schedule passed all six sequences at both optimization
levels. O0 took 175.31 seconds and O2 took 120.90 seconds; each emitted
3,399,774 canonical logical records and 13,209,324,735 payload bytes. These are
worker measurements, not an estimate of whole-workflow speedup.

The isolated causal audit also passed 64 attempts: 30 targeted refusals, 32
whole-state same-session refusals and two positive four-root runs. Caller and
cleanup hardware boundaries, 241,328 byte-exact retry records and 160 real
resource deletions were checked. The changed game constructor IAT cell is
refused at its next actual source read; an already completed read does not
receive an immediate refusal claim.

Persistent source comparison passed all twelve sequences and 1,488 phases:
63,984 whole pages before and after, 1,152 ordered registrations, 96 Lockit
CALL/RET pairs, 684 normal game FS accesses, 456 complete installed/restored
12-byte records and 108 new header-byte derivations. Scheduler continuity and
actual host returns were checked separately within the same reader.

The complete provider lifecycle comparison passed all twelve sequences with
24,636 complete State/CPU/FX checkpoints, actual owner frees, critical-section
deletion and post-HeapDestroy observations. Paired data passed all 1,488 phases,
including 122,016 ordinary page relations and 2,976 separate whole loader-page
relations. Independent source/provider/paired/control and configuration reviews
passed; final acceptance rehashed all 11,809 physical dependencies, including
every historical capture reused during iterations. The four roots now receive
inventory credit. Original provider observations stop at the constructor's API
return before its epilogue and the destructor's pre-RET; their post-RET CPU is
source-derived, with bounded actual Windows API effects.

The first complete paired run found no data mismatch but failed its coverage
assertion: one auxiliary byte lacked its provenance relation, and a counter
combined ordinary and loader pages incorrectly. The additive corrected comparer
includes the physical `50068B` store to `60BF90` and keeps both page counts
distinct. Its fresh full rerun and independent nine-field source review passed;
the failed receipt remains preserved.

Two native admission gaps were found before the combined rerun. Two functions
read the exception-chain pointer before pushing their handler data, unlike the
inherited prolog. Their exact early-read variant now retains genuine CALL
provenance and checks all twelve installed bytes after the pushes. The new
owner stores and publications now have their own exact contracts. Generic MFC
publication counting is suppressed only at those eight sites so each pointer
publication is recorded once. Failed workers and earlier preparations remain
preserved.

Local iterations reuse the identities of historical `.mwb` capture payloads,
which the native worker does not consume. Changed code, game/DLL inputs,
current workers and fresh capture payloads are still physically verified.
Final acceptance must rehash the complete conflict-normalized dependency union,
including every reused historical payload. The change removes repeated reads
of roughly 117 GB of historical payloads from local compile/run iterations.
