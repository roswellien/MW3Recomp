# Native command-line writer candidate

This separate candidate implements the exact eleven-byte staged CRT writer at `0x7800188C`: CALL through provider IAT `0x7802E034`, return to `0x78001892`, and MOV EAX to `_acmdln` at `0x78037174`. The owning provider import is `KERNEL32.dll!GetCommandLineA`. The original next instruction at `0x78001897` is outside the admitted writer. An explicitly authored capture jump ends the experiment there; it supplies no original RET, DllMain, process-attach, or complete startup claim.

[GetCommandLineA](https://learn.microsoft.com/en-us/windows/win32/api/processenv/nf-processenv-getcommandlinea) returns the current process's system-owned ANSI command-line string. The service does not free, modify, decode or parse that borrowed string. It obtains its own actual host snapshot with bounded readable-region and NUL checks, copies the bytes into an owned checked guest allocation, and returns a strong 32-bit GuestAddress in guest EAX. The host pointer remains separate 64-bit metadata in a native capture. It is never truncated into guest state or asserted equal to a guest address. The bounded scan includes one terminator and admits at most 131072 bytes; empty input still has its actual NUL byte.

The translated writer must perform its own actual store to the provider global. The data-import adapter validates the game image's unique `MSVCRT.dll!_acmdln` owner at `0x5BB518`, preserves its original IAT DWORD, and resolves it to the exact provider-global guest address only after measured writer completion. A subsequent checked DWORD load must yield the owned live guest buffer. The provider's file DWORD zero establishes identity only. No original probe buffer or reference-projection fixture initializes this production buffer.

The new adapter is provider-specific because frozen Runtime r9 authorizes imports owned by its game metadata, not this provider's KERNEL32 IAT. It validates the exact staged DLL, actual provider import descriptors/name/slot and initial IAT bytes, RX writer bytes, RW global source and ownership. It preserves raw provider and game IAT cells. Its declared semantic import resolution returns an authored service gate only to this exact compiled CALL; that gate is a guest route identifier, never a host pointer or an invented game import. The actual Windows target pointer, named resolution, loaded owner module/base/RX memory and disk identity are recorded before and after where feasible. No complete Windows dependency closure is implied.

There are no stack arguments. The compiled actual CALL pushes `0x78001892` at entry ESP minus four; the typed service must verify that actual frame and return through it with zero argument cleanup. The writer then stores guest EAX. At the authored capture boundary, ESP equals the writer entry ESP. No RET is invented. ECX/EDX/arithmetic flags and service-volatile SIMD are retained as actual original observations and remain unspecified unless recovered guest code consumes them. The eleven admitted bytes consume only returned EAX; behavior after the outer capture is unresolved. Native preservation of other software State fields is an explicit representative policy and is checked separately from actual host FX/legacy ENV and host restoration.

The registry borrows a persistent Runtime that outlives it and owns only mappings/allocations it successfully acquires. It admits once, retains its first typed fault, never marks a partial writer complete, and releases partial guest allocations on failure. Preexisting mappings survive collision denials. Ready-state integrity checks bind raw IATs, writer source, actual stored pointer and live bounded NUL-terminated guest bytes. Unknown imports/data slots, changed source/owner/continuation, unreadable or readonly required memory, wrong State/frame, reentry, stale pointers, buffer/global mutations and reuse after fault are causal denials. Externally swallowed arbitrary GuestMemory exceptions and adversarial host mapping replacement remain outside the narrow adapter API.

The discriminating experiment explicitly selects each exact worker with `lpApplicationName` and independently supplies the same authored Windows command-line fixture. Input/output paths and the reserved-child marker are child-process-local task-specific environment variables. The original broker preserves that command line when creating its suspended reserved child. No user/system environment variable is changed or unrelated environment value reported. Each original/native process queries its own actual GetCommandLineA; the supplied logical fixture and actual observed ANSI strings are serialized separately. Windows alterations are measured differences, never overwritten to make the oracle pass. Native execution receives no original after observations.

Directed fixtures cover masked control words, empty TOP values, authored GPR/flags and dirty opaque State and a small set of quoting/spacing command-line inputs. Raw records must capture complete CPU/State, whole owned pages, independent host source snapshot and guest buffer, actual CALL/service/capture routes and ordered memory accesses, full separate hardware FX/legacy ENV and host restoration. Independent observer corruptions and compiled identity/permission/ownership/partial-failure controls distinguish byte fidelity from pointer-domain equality. Original software State and per-access events remain unobserved. The frozen reference-only registry and all prior gates remain untouched. This candidate does not attach the complete CRT or enter the native menu.

Original State/access events remain unobserved. The service's native semantic IAT resolution leaves raw game/provider cells intact. All initialization-attempt failures and admission failures are terminal in this new registry; the first typed fault is retained and a corrected context needs a new registry. The API admits no retry path analogous to a reusable unentered SPI Context. Direct arbitrary GuestMemory operations bypass the typed adapter and can throw raw MemoryFault; those do not automatically poison this registry. The adapter catches required memory operations with a contextual typed site; raw GuestMemory carries a reason but no precise failing internal address, so it does not claim a complete general memory-fault report.
