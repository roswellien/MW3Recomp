**Static evidence:** `0x577590` copies descriptor height/width/pitch/pointer into a surface record: record+0/+4/+8/+0x10; +0x14 marks locked and +0xC is set to 1. ## GDI, failure, and destruction

**Static evidence:** S3 `/bodies/258` sets up GDI **after** successful DirectDraw/mode setup: GetDC at `0x579D94`→`0x80934C`; CreateCompatibleDC at `0x579DA1`→`0x809350`; top-down 16-bit BI_BITFIELDS DIB at `0x579E25`→`0x809354`, using dimensions and RGB-mask globals. SelectObject and PatBlt follow at `0x579E38`/`0x579E58`. These returns are not checked in this body. **Inference:** These resources may support compatibility/fallback operations, but no complete GDI presentation route or recovery from DirectDrawCreate failure is established. A pure GDI windowed bypass would require separate admission.

**Static evidence:** `0x577310` loads IAT `0x5BB074` into ESI and invokes the same imported function with each of the three GDI globals, then calls `0x5788B0`. Fresh S4 import-table inspection resolves that slot to GDI32.dll DeleteObject, including the calls supplied with DC values. This unusual shared cleanup must be preserved/checked against the provider; correct DC/bitmap destruction and selected-object restoration are unknown here. Do not replace it with guessed DeleteDC/ReleaseDC behavior. S2 `/bodies/32`, S4 import table.

**Static evidence, continuation 2026-10-11:** GDI has a concrete intermediate bitmap path. Setter stores at `0x57A02F`/`0x57A039` install `0x72F394→0x577BA0` and `0x72F398→0x577BD0`. The first callback reads signed 16-bit dimensions from incoming ECX record+4/+6, calls PatBlt through IAT `0x5BB0A4` at `0x577BBA` with origin zero and ROP 0x42 (BLACKNESS), stores memory DC `0x809350` through incoming EDX, and returns 1 without testing PatBlt. S2 `/bodies/90`, `/bodies/49`; S4 import table. **Inference:** This callback exposes a shared drawing DC rather than acquiring a fresh owned DC per call; caller behavior and synchronization remain unknown.

**Static evidence plus ABI inference:** The second callback calls GetObjectA through IAT `0x5BB078` at `0x577BEA` on bitmap `0x809354`, requesting a 0x18-byte BITMAP. It ignores the returned byte count, reads the resulting bits pointer at `0x577BF0` and stride at `0x577C20`, then copies nonzero 16-bit pixels into incoming ECX record+0x10. Its source advances by the GDI stride per row; destination advances by two bytes per pixel, with no separate destination-row adjustment. Zero source pixels leave destination words untouched. Signed width/height <=0 skip the corresponding loops; the callback returns 1 even after unchecked GetObjectA. S2 `/bodies/50`, S5. **Inference:** This supports GDI bitmap-to-surface-memory composition, potentially for glyph/overlay drawing; it does not establish the caller, valid memory bounds, destination format, or final window presentation. It must not be generalized to arbitrary destination pitch or alpha blending.

**Bounded static search:** The cited linear listing has 11 direct absolute references to the three GDI globals (setup, teardown and the two callbacks above). Its sole direct call through BitBlt IAT `0x5BB06C` is at `0x590AFB`; nearby instructions create a compatible DC at `0x590AAC`, select an object at `0x590AC3`, use SRCCOPY 0x00CC0020, then call DeleteDC at `0x590B02` through `0x5BB094`. These sites are in S3's linked linear listing, not an admitted complete video callback body. Their receiver/caller connection to the video globals and menu remains unknown. This bounded search excludes register-mediated accesses, aliases, other modules and unretained paths; it neither proves a complete GDI fallback nor proves one absent.

**Static evidence:** `0x578740` releases and clears globals for auxiliary interfaces/surfaces, clipper `0x80935C`, and palette `0x809364`. Before releasing records at `0x8027C4`/`0x8027E8`, it conditionally calls slot+0x98 (PageUnlock) and respects attached/backbuffer flags `0x8027C0`/`0x8027E4`. PageUnlock failure can return early with later cleanup incomplete. `0x5788B0` destroys fallback resources via `0x57BB00`, conditionally releases more surfaces, calls DirectDraw4+0x4C (RestoreDisplayMode) at `0x578946`, releases it at `0x578951`, and clears `0x809358`. S2 `/bodies/149`, `/bodies/146`, `/bodies/55`.

**Static evidence / inference:** Successful resource construction stores surface/texture references at wrapper+0/+4/+8; temporary source texture QI is released at `0x57B61D`. Failure cleanup at `0x57B63B` onward conditionally releases local references. `0x57BB00` releases those three wrapper references and frees the wrapper, with special handling for `0x80931C`/`0x809320` until teardown flag `0x802710` permits destruction. ## Smallest implementable slice and unlock

**Inference — proposed bounded slice:** Implement `0x577D40` creation/QI with typed guest COM handles, exact output writes/status branches, and the matching owned DirectDraw teardown boundary. A harness can exercise success and injected creation/QI failure while recording reference transitions. Stop before `0x577CD0` surface/mode setup and carry the real interface/global state forward; do not return application/service initialization success from that stop. `0x5772F0` can be integrated only after the actual window side effects in `0x576EE0` are supported. This is the smallest useful provider boundary, not a complete video service.

**Inference — prerequisites:** hash-admitted guest image and address mapping; typed guest pointer/vtable dispatch and x86 calling conventions; initialized adapter receiver `0x809644`; actual provider selection/ABI evidence; error/report helper contract; reference ownership including failure output behavior; and a real owned window receiver for the enclosing path. Complete CRT environment and required 144-root initialization, MFC application/frame receiver lifetime, localization/configuration and the pre-frame reader ABI remain integration prerequisites owned by other lanes.

**Inference — next presentation slice:** Once branch selection is observed, admit just its required cooperative/display mode, primary/backbuffer/offscreen/clipper construction, pixel format, lock/upload/unlock, fills/blits or flips, palette behavior and ordered cleanup. A fullscreen/exclusive request is present in the recovered code; choosing a modern windowed mode is an additional behavior change. Callback/resource creation can also lead into Direct3D texture/device work, so a software-only menu closure is not yet proven.

**Inference — unlock:** This contract provides concrete boundaries for connecting an owned native frame/window to the game's graphics service and later uploading/presenting parsed menu assets. It would let integration stop at the next unsupported video operation with truthful carried state. It does not close MAINMENU parsing, widget/font/bitmap contracts, input/audio, startup state transitions, message-pump/focus behavior, or normal shutdown.
